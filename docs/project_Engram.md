# Technical Architecture: Cephalon Archive

This document details the complete infrastructure of the project, divided into five
fundamental pillars. The architecture is designed to link a complex vector database
derived from the Evolution Engine to multiple interfaces (Desktop, Discord) via a
real-time AI backend.

## 1. Orchestration & Deployment

The infrastructure relies on a strict separation between heavy hardware inference
and application logic.

* **Local Inference (Host):** The LLM model (Qwen3.8-27B) runs natively on the
  host machine via LM Studio. This guarantees exclusive and unrestricted access
  to the GPU's VRAM. The server exposes an OpenAI-compatible REST API on
  `localhost`.
* **Containerization (Docker Compose):** Application services are isolated in
  separate containers to ensure environment reproducibility:
  * PostgreSQL database (with `pgvector` extension).
  * API backend (Python/FastAPI).
  * Standalone Discord Bot service.

## 2. ETL Pipeline (Extract, Transform, Load)

The data lifecycle, from developer sources to vector injection.

* **Extraction (Scraper):** Automated scripts targeting raw Wikitext and
  official game exports.
* **Transformation (Parser):** Algorithmic processing of `.dialogue.json`
  files. The parser cross-references this data with localization dictionaries
  (`en.json`) to reconstruct the exact causal tree of discussions (nodes,
  edges, conditions).
* **Vectorization (Embedding):** Splitting lore and dialogues into contextual
  *chunks*. Using a multilingual embedding model (e.g. BAAI/bge-m3) to store
  vectors in PostgreSQL (`pgvector`), enabling queries in English against
  French-language data and vice versa.

## 3. Central Backend (FastAPI & RAG)

The microservice acting as an intelligent router between the database,
LM Studio, and clients.

* **Document Endpoint (HTTP POST):** Handles encyclopedic RAG. Cosine
  similarity search in `pgvector`, construction of the *Super-Prompt* including
  sources, and structured response delivery.
* **Roleplay Endpoint (WebSockets):** Handles KIM terminals. Maintains a
  bidirectional connection to stream tokens generated by the LLM in real time.
* **State Management (Sliding Window):** Async cache retaining the latest
  exchanges of the active session to give the AI short-term conversational
  memory.

## 4. Client Application (UI/UX)

The evolution of the web interface toward an isolated native desktop application.

* **Desktop Wrapper:** Encapsulation of the Vue.js interface via a desktop
  framework (Tauri or Electron) for local software operation.
* **Encyclopedia Module:** Static interfaces optimized for browsing the Codex,
  Fragments, Quests, and Universe.
* **KIM Simulator:** Responsive messaging interface. Consumes the WebSocket
  stream to display messages organically, including asynchronous status
  indicators (e.g. "Amir is typing...").

## 5. The Loremaster (Discord Bot)

A standalone client focused on narration and community education.

* **Technology:** Independent server (developable in Java via the JDA framework
  or in Python).
* **Slash Commands (`/`):** Intuitive command interfaces for querying the
  central API about specific time periods, factions, or characters.
* **Advanced Formatting:** Systematic use of Discord *Embeds* to hierarchy
  information, display lore-associated images, and neatly list sources
  extracted by the RAG pipeline.
